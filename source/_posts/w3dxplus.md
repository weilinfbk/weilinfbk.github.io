把街机塞进 iPad 3：Re3DXPlus 如何用“静态重编译”移植《湾岸 3DX+》

一、这个项目在做什么
Re3DXPlus 的作者是 Bilibili UP 主「高橋涼介のFC」（GitHub：Allannn-sudo）。目标很明确：让 2010 年的街机游戏《湾岸 MIDNIGHT MAXIMUM TUNE 3DX+》在老旧的移动设备上原生运行——

· iPad 3：iOS 6.1.3（越狱），OpenGL ES 2.0，1024×768 60fps
· iPhone 4：iOS 6，同一套代码，3:2 画面
· Android：arm64，Android 9+，Vulkan 渲染器，也可回退到 OpenGL ES 3
但它不是模拟器。这是理解整个项目的起点。



二、核心思路：物理“重编译”，其余“重写”
模拟器在运行时逐条翻译原版 CPU 指令，开销大、兼容性坑多。Re3DXPlus 走的是另一条路：
街机的赛车物理和比赛逻辑，由 tools/recomp/ 把原版 i386 程序静态重编译成 C；其余部分（渲染、菜单、HUD、声音、对战）照着原版逆向结果重写。
静态重编译的原理并不复杂：把原版 x86 指令一条条“抬升”为等价的 C 代码，再用本地编译器为目标平台（arm64）重新编译，最终得到的是一个原生程序，而不是运行在解释器里的“虚拟街机”。理论上能做到逐位一致，性能也远好于实时模拟。
代价是：重编译只负责“物理和比赛逻辑”，渲染管线、UI、音频这些必须另起炉灶



三、技术拆解：三条并行的工程线

1. 物理层：用 Unicorn 模拟原版，生成 C 代码
生成物理代码不是靠“读汇编手写”，而是用 Unicorn 模拟器直接运行原版程序，调用原版自己的查表函数，把结果固化成 C 头文件（22 个）和重编译后的物理代码 phys_rc.c。从同一份原版数据生成的结果是确定的。

2. 渲染层：iOS 走老 GL，Android 走 Vulkan
iOS 端用 OpenGL ES 2.0，这是 iPad 3 能跑 60fps 的现实选择。Android 端默认 Vulkan，同时提供一个 GLES→Vulkan 转换层（vkgl.c），也可以切回 OpenGL ES 3。着色器源码先写成 GLSL，再自动转成 SPIR-V 给 Vulkan 用。
这意味着同一套游戏逻辑，在两个图形 API 差异巨大的平台上都能跑起来。

3. 素材与工具链：从“你的原版数据”生成一切
仓库里不包含任何原版内容——没有模型、贴图、音乐、打包好的 ipa/apk。所有素材都靠 tools/ 下的 Python 脚本，从你自己合法取得的原版街机数据中转换生成：
· 东京地图（早/晚）、路牌、天空：pack_tokyo.sh
· 车辆（含 aero、轮毂、剧情对手车）：pack_cars.py
· 菜单、HUD、小地图、贴纸、路上车流……各自有对应打包脚本
Android 端还可以用 Real-ESRGAN 放大贴图，再转成 ASTC 压缩格式。



四、构建与运行：你得自己“喂”原版数据

整个流程要求你把原版数据文件夹放在仓库旁边，命名为 Wangan Midnight Maximum Tune 3DX+ (Japan)，里面包含 main 和 data/。然后：
1. 生成代码表和物理：sh tools/gen_from_original.sh --phys
2. 转换素材：按需运行各个打包脚本
3. 构建：iOS 用 build.sh（macOS + Xcode + theos），Android 用 build_android.sh（Vulkan 或 VK=0 回退 GLES3）
联网对战可以跑 tools/vs_server.py（UDP 27015，最多 4 人），iOS 之间还能走蓝牙。



五、法律与边界：它明确不做什么
项目作者在 README 里把边界写得很清楚：

· 非官方：不是万代南梦宫的发行版本。
· 仓库零原版内容：代码和工具是 MIT 许可，但许可只覆盖移植代码本身，不覆盖原版游戏及其任何素材。
· 你需要自己合法取得原版数据，且不要在 issue/PR 里上传原版文件或转换产物。

换句话说：这是一个技术研究项目，它的“可构建性”以你手上有合法原版数据为前提。



六、这个项目的技术看点

如果从工程角度总结，Re3DXPlus 的价值不在于“能玩”，而在于它展示了一套混合移植方法论：

对性能敏感的确定性逻辑（物理、比赛规则）→ 静态重编译，保留原版行为，原生执行；
对平台敏感的呈现层（渲染、UI、音频）→ 逆向重写，针对目标设备重新实现；
所有内容资产→ 从用户自己的原版数据转换，仓库本身保持“干净”。

这种“重编译核心 + 重写外围 + 工具链生成素材”的组合，比纯模拟器更重工程、比完全重写更保真，也是近年来静态重编译移植思路的一个具体实践。
