Re3DXPlus 这个名字容易让人误会。我一开始也以为是那种 AI 驱动 3D 头部的项目，点进去才发现，它是《湾岸 MIDNIGHT MAXIMUM TUNE 3DX+》在 iOS 和 Android 上的非官方原生移植研究项目。作者是 B 站 UP 主「高橋涼介のFC」，GitHub 叫 Allannn-sudo。

目标很直接：让 2010 年的街机赛车游戏在 iPad 3、iPhone 4 这种老设备上本地跑起来，不是串流，也不是云游戏。

它最值得写的地方，是技术路线跟模拟器完全不一样。

模拟器是运行时逐条翻译原版 CPU 指令，一边解释一边跑。Re3DXPlus 则把街机的赛车物理和比赛逻辑，用 tools/recomp/ 静态重编译成 C 代码，再用本地编译器编成 arm64 原生程序。等于把原版 x86 指令一条条“抬”成等价的 C，最后得到一个能直接跑的原生二进制，而不是套一层虚拟机。

好处是性能和保真度都比实时模拟好，理论上可以做到逐位一致。代价是重编译只覆盖物理和比赛规则，渲染、菜单、HUD、声音、对战这些，全得照着原版逆向结果重新写。

所以这个项目其实是三条线并行。

物理层不靠人读汇编手写。作者用 Unicorn 模拟器直接跑原版程序，调用原版自己的查表函数，把结果固化成 22 个 C 头文件和重编译后的 phys_rc.c。同一份原版数据生成出来的结果是确定的，既保真，又不用手工逆向每一行。

渲染层，iOS 端用 OpenGL ES 2.0。别嫌老，iPad 3 能跑 1024×768 60fps 靠的就是它。Android 端默认 Vulkan，还写了一个 GLES→Vulkan 的转换层，也可以切回 OpenGL ES 3。着色器先写 GLSL，再自动转 SPIR-V。同一套游戏逻辑，在两个图形 API 差异很大的平台上都能落地。

素材层，仓库里没有模型、贴图、音乐，也没有打包好的 ipa 或 apk。所有素材都得用 tools/ 下的 Python 脚本，从你自己合法取得的原版街机数据里转换出来。东京地图早晚、路牌、天空、车辆、轮毂、剧情对手车、菜单、HUD、小地图、贴纸、路上车流，各自有对应的打包脚本。Android 端还能用 Real-ESRGAN 放大贴图，再转 ASTC。

构建流程也围绕这个逻辑：把原版数据文件夹放在仓库旁边，命名成 Wangan Midnight Maximum Tune 3DX+ (Japan)，里面要有 main 和 data/。然后跑 gen_from_original.sh --phys 生成代码表和物理，按需跑素材脚本，最后 iOS 用 build.sh、Android 用 build_android.sh。联网对战可以跑 tools/vs_server.py，UDP 27015，最多 4 人，iOS 之间还能走蓝牙。

作者在 README 里把边界写得很清楚：非官方项目，不是万代南梦宫的发行版；仓库零原版内容；代码和工具是 MIT，但许可只覆盖移植代码本身，不覆盖原版游戏和素材；你需要自己合法取得原版数据，也别在 issue 或 PR 里上传原版文件或转换产物。所以它本质上是个技术研究项目，不是“下载即玩”的整合包。

我觉得它值得看的地方，是这套混合思路：对性能敏感的确定性逻辑做静态重编译，对平台敏感的呈现层做逆向重写，素材全部从用户自己的原版数据生成。比纯模拟器工程量大，比完全重写保真，算是静态重编译移植的一个完整实践。老 iPad 3 能跑出 60fps，这点挺有说服力。
